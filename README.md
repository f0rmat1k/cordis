# cordis

Общий голосовой звонок в браузере с нейросетевым шумоподавлением. Открыл сайт — и ты уже в звонке
со всеми, у кого он открыт. Комнат, аккаунтов и контактов нет.

- **Звук** идёт напрямую между участниками: каждый соединён с каждым (WebRTC, кодек Opus 64 кбит/с).
  Сервер только знакомит их. Такая схема хорошо тянет до 6–8 человек: каждый отправляет свой голос каждому.
- **Шумодав** работает в браузере того, кто говорит. Режимы (переключаются прямо во время звонка):
  - **DeepFilterNet3** — нейросеть, по умолчанию. Лучше всех режет клики, клавиатуру и фон.
    Ползунок «Сила подавления» — предел ослабления шума в дБ: меньше — голос естественнее, больше — тише фон.
    Модель весит ~24 МБ: сервер сам скачивает её в `models/` при первом старте, браузер — при первом включении режима.
  - **GTCRN** — маленькая нейросеть, на слабых устройствах. Бывает агрессивной и «рвёт» голос.
  - **RNNoise** — старая лёгкая нейросеть, клики почти не убирает.
  - **Встроенное в браузер** — WebRTC-шумодав Chrome/Firefox, убирает только ровный фон (гул, шипение).
  - **Выключено**.
- **Имя** выдаётся случайное («ХитрыйЁж42») и запоминается браузером; поменять можно в настройках.
- Видно, кто в звонке, кто говорит (зелёная обводка) и у кого выключен микрофон.
- Браузеры не включают звук, пока по странице не кликнули. Поэтому, если вход был без клика,
  сверху появляется кнопка «Включить звук»: до неё вы не слышите остальных, а они — вас.

## Боевой сервер

Живёт на домашнем сервере. **Выкатка — просто пуш в `main`**: задание
`Cordis deploy` раз в минуту забирает `main`, при смене `package.json`/`package-lock.json` делает `npm ci`,
перезапускает приложение и проверяет, что оно отвечает. Не поднялось — откат на прошлый коммит.
Скрипты, логи и описание — в `C:\mds-deploy` на сервере (`deploy-cordis.ps1`, `logs\cordis-*.log`),
nginx — в `config/nginx.conf` репозитория mds-rest. Не правь отслеживаемые файлы прямо на сервере:
`git merge --ff-only` перестанет проходить, и деплой встанет.

## Запуск на своём ПК (белый IP)

Браузеры дают доступ к микрофону только по **HTTPS**. Порты 80/443 не нужны: сайт работает на отдельном порту
(по умолчанию 8443), а сертификат Let's Encrypt Caddy получает через DNS-проверку бесплатного [DuckDNS](https://www.duckdns.org).

1. На duckdns.org войти, создать поддомен (например `mycordis`), указать в нём свой внешний IP и скопировать token.
2. Установить Caddy и добавить в него модуль DuckDNS:
   ```bash
   winget install CaddyServer.Caddy
   ```
   ```bash
   caddy add-package github.com/caddy-dns/duckdns
   ```
   Если `add-package` не сработает, готовую сборку можно скачать на https://caddyserver.com/download, отметив пакет `caddy-dns/duckdns`.
3. Поставить зависимости (один раз):
   ```bash
   npm install
   ```
4. На роутере пробросить на этот ПК **TCP 8443** (или другой выбранный порт) и открыть его в брандмауэре
   (PowerShell от администратора):
   ```powershell
   New-NetFirewallRule -DisplayName "cordis" -Direction Inbound -Protocol TCP -LocalPort 8443 -Action Allow
   ```
5. Первый запуск (параметры запомнятся в `local-config.json`):
   ```bash
   powershell -ExecutionPolicy Bypass -File start.ps1 -Domain mycordis.duckdns.org -Token ВАШ_ТОКЕН -Port 8443
   ```
   Дальше достаточно `start.ps1` без параметров. При первом запуске получение сертификата занимает до минуты.
6. Отправить друзьям `https://mycordis.duckdns.org:8443`.

Если на машине с основным сайтом стоит nginx/Caddy и у сайта есть свой домен, можно вместо этого завести
поддомен (например `call.вашсайт.ru`) и проксировать его на `http://<IP этого ПК>:3000` с поддержкой WebSocket.
Тогда Caddy здесь не нужен.

Для локальной проверки без HTTPS хватит `npm start` и http://localhost:3000. На `localhost` микрофон работает и без сертификата.

## Если звонок соединяется, но звука нет

Откройте сайт с `?debug` (`https://адрес/?debug`) — внизу появится панель с состоянием соединения
с каждым участником и журналом событий; кнопкой «Скопировать» её можно отправить текстом.
Работает и на телефоне. Если у обоих есть кандидаты `srflx`, а проверки пар — `failed`,
то дело в NAT, см. ниже. Если `srflx` нет вовсе — до STUN-сервера не достучаться.

Чаще всего это значит, у кого-то из собеседников строгий NAT (бывает у мобильного интернета и некоторых провайдеров)
и прямое соединение не пробивается. Нужен TURN-сервер, который будет пересылать звук.
Например, бесплатный тариф [Metered](https://www.metered.ca/stun-turn) или свой coturn. Параметры передаются через переменные окружения:

```bash
TURN_URL=turn:example.com:3478 TURN_USER=user TURN_PASS=pass npm start
```

## Устройство

| Файл | Что делает |
|---|---|
| `server.js` | Раздаёт страницу, ведёт список участников звонка, пересылает сигналы WebRTC через WebSocket |
| `public/audio.js` | Цепочка микрофона: getUserMedia → шумодав (AudioWorklet + WASM) → WebRTC |
| `public/app.js` | Интерфейс, логика общего звонка (соединение с каждым участником) |
| `Caddyfile`, `start.ps1` | HTTPS и запуск |

Шумодавы взяты из [@sapphi-red/web-noise-suppressor](https://github.com/sapphi-red/web-noise-suppressor).
